# 工程实现说明

> 工程已按「从空工程新建」的方式落地，不再 fork `InteractiveChecklists`。
> 下面记录实际做了什么，以及和最初方案不一致的地方。

## 0. 为什么放弃 fork 骨架

骨架 117 个 Kotlin 文件按功能拆分的权重：

| 模块 | 占比 |
|---|---|
| 地图 `ui/maps` | 43.6% |
| DataPad | 8.9% |
| PDF 阅读器 | 6.8% |
| 战术单位 | 4.7% |
| 检查单 | 2.7% |
| 其它 | 33.3% |

本项目需要复用的只有 PDF 阅读器那 6.8%，而骨架自带的地图、DCS 配套逻辑、QR 扫描要一并背下来。同时骨架是 CC BY-NC-SA 4.0，改后的工程外传需同许可并署名。从空工程新建没有这些负担。

空工程要写的代码约 1500 行，全部落在 `app/src/main/java/com/oguricap/efb/`。

## 3. 数据层

不用 Room。`ChartIndex` 用 `SQLiteDatabase.openDatabase(path, null, OPEN_READONLY)` 直接打开 assets 拷贝出来的预置库。

原因：Room 的 `createFromAsset` 会校验预置库里的 `room_master_table`（存 schema 的 identityHash），`naip_index.py` 用裸 sqlite3 生成的库没有这张表，调用抛 `IllegalStateException`。

表结构：

```sql
CREATE TABLE charts(
    id TEXT PRIMARY KEY,
    icao TEXT,
    airport TEXT,       -- 机场中文名，如「北京首都」
    chartType TEXT,     -- ADC/GMC/APDC/SID/IAC/STAR/AOC/ATCSMAC/CODING/ENR/OTHER
    title TEXT,
    file TEXT,          -- 相对路径，用 根目录 + file 拼绝对路径
    rwys TEXT           -- 逗号拼接，只显示不筛选
);
CREATE TABLE airports(
    icao TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    chartCount INTEGER NOT NULL
);
```

查询：

| 方法 | 用途 |
|---|---|
| `airports()` | 全部机场，按四字码字典序 |
| `airport(icao)` | 单个机场，用于机场页标题 |
| `charts(icao)` | 某机场全部航图，按图型顺序 + 图名排序 |
| `searchAirports(q)` | 四字码前缀 + 中文名包含，中文匹配置顶 |
| `searchCharts(q, limit)` | 只按图名包含匹配；四字码不再展开该机场的全部航图 |

`LIKE` 的 `%` 与 `_` 会被转义，输入这两个字符不会退化成全表匹配。

## 4. 界面

四个路由：搜索页 → 机场页 → 阅读页，以及设置页。

| 页面 | 行为 |
|---|---|
| 搜索页 | 顶部搜索框边打边过滤；**机场大类卡片置顶**（四字码精确命中时整卡高亮，显示中文名与张数），点进去按图型看图；只有查询词完全没命中机场时才列图名匹配；缺权限或缺目录时顶部给出可点击的提示卡 |
| 机场页 | 分组默认全部折叠，组标题显示中文名与张数，点标题展开；条目右侧显示跑道号；顶部常驻「选择离场 / 进场航图」引导卡，选中后置顶显示 |
| 阅读页 | 纵向连续滚动，双指缩放（1–6 倍，以捏合中心为锚点），右上角反色开关 |
| 设置页 | 航图目录、所有文件访问权限、索引导入、反色开关 |

主题：列表跟随系统深浅色，颜色是深红配灰蓝；阅读页固定白底，深色环境下用反色开关。

## 5. 阅读页的实现要点

- 按屏幕宽度渲染，不按 PDF 原始 DPI。实测 1280 px 宽足够看清航图文字。
- 位图用 `RGB_565`，单页内存是 `ARGB_8888` 的一半。
- `LruCache` 上限 3 页，超出时让旧位图自然成为垃圾，不主动 `recycle()`——刚滑出屏幕的页可能仍被合成线程引用。
- 当前页显示完之后立刻预渲染下一页，翻页时直接命中缓存。
- 只拦截双指手势，单指留给列表滚动。
- 离开阅读页时 `renderer.close()` + `pfd.close()`，`close()` 幂等。

## 6. 文件访问

`MANAGE_EXTERNAL_STORAGE` + 直接 `File` 读取。首次启动在系统选择器里选一次 `/sdcard/飞行/AIP航图库`：

- 选择器只用来让用户指认目录，避免路径写死；
- 选完立刻校验：目录存在且索引里第一条航图能在其下找到，否则提示「请选中『AIP航图库』那一层」；
- 校验通过后存进 SharedPreferences，之后读取一律走 `File`；
- 航图目录只读，App 不往里写任何东西（连 `.nomedia` 都不写）。

## 7. 换索引

设置页「索引 → 导入新的 charts.db」，用系统文件选择器选一个 `charts.db`，校验能打开后替换私有目录里的副本并重新加载。换航图库不用重编 APK。

## 9. 工具页与自定义检查单（1.3.0）

在 1.2.2 基础上加了两块：底部第 4 个标签「工具」（内嵌航路生成器与油量计算器两个单文件网页），
以及检查单页的「自定义检查单」。**没有新增任何 Gradle 依赖，没有申请网络权限，`largeHeap` 仍是 false。**

### 9.1 三条红线

| 红线 | 落地方式 |
|---|---|
| 不预置、不打包任何 Navigraph 派生数据 | `app/src/main/assets/` 下只有两个**无数据版** HTML；`.gitignore` 加了 `navData/`、`co-routes/`、`*.dat`、`*.fms`、`*.fms.bak` |
| 数据变换只在用户设备上、对用户自己导入的数据、运行时发生 | App 只做「读 SAF 流 → 按块喂给网页」，解析与坐标编码全在网页里（`NavParser.parse` + `PackCodec.encode`） |
| 不开 `largeHeap` | 分块 192K 字符流式读，`CharArray` 复用，绝不 `readBytes()`；注入完置 null |

### 9.2 网页工具怎么装进 WebView

`assets/tools/*.html` 在磁盘上**字节级原样**（`cmp` 与 `Walker'sHTML/` 下的原版一致，sha256 相同）。
`ToolContract` 读成 String 后在**内存里**按锚点插两处胶水，再交给 `loadDataWithBaseURL`；不写磁盘、不跑脚本。

| 补丁 | 锚点 | 插入内容 |
|---|---|---|
| 桥 | `</script>\s*</body>`（唯一序列） | 一个新的 `<script>` 块，内容是 `assets/tools/efb_shim.js`，把 7 个顶层 const 挂到 `window.__EFB__` |
| 导出 | `function downloadJson(filename, obj) {`（全文唯一） | 函数头早退 guard，转给 `Android.exportJson` 写文件 |

锚点、`requiredConsts`、shim 路径、距离注入脚本全在 `assets/tools/efb_patches.json`（非 Kotlin）。
**正常升级 0 处 Kotlin 改动；锚点漂移只改这两个非 Kotlin 资源。**

为什么桥必须单独成块：主脚本里任一错误会中止整段，`DOMContentLoaded` 注册不上、`UI.init()` 不跑、整页废掉；
独立块里报错只炸桥，主页面无恙。另外 7 个对象都是顶层 `const`，`window.UI` 恒为 `undefined`，只能按裸名引用。

### 9.3 出包期门禁

`app/src/test/java/com/oguricap/efb/ToolAssetsContractTest.kt`，7 个用例，是这套升级方案**唯一的把关点**：

1. 航路页 7 条 `const X = (function` 各命中恰好 1 次；`</script>\s*</body>` 唯一；`downloadJson` 签名唯一；
2. 导出机制仍是 `URL.createObjectURL` / `a.download` / `a.click()` 各 1 处（换了导出机制就会红）；
3. 油量页 `#dist` / `#aircraft` / `#regime` / `calc()` / `runSelfTests()` 各 1 处，且只有**一个**「皮肤」补丁（不含桥）；
4. 配置里每个锚点在对应文件命中数恰好 1，且都声明了幂等 marker；
5. 两个 HTML 单文件自包含：无 `http(s)://`、无 `<script src`、无 `<link href`、无 `@import`、无 `type="module"`（**不按 `fetch(` 判**，843 行那处是死分支）；
6. `applyPatches` 产物里 `window.__EFB__` 与 guard 各 1 处、函数体完整、重复调用不叠加；
7. 版本正则可提取且非空，`bridgeVersion` 在 Kotlin 常量 / 配置 / shim 三处一致。

**版本号故意不钉死**：换新版 HTML 本来就会改版本，钉死等于每次升级都红。门禁只保证「还能提取到」+「桥版本三方一致」。

两次演练已实测：

| 演练 | 操作 | 结果 |
|---|---|---|
| A 正常升级 | 把 `route_gen.html` 的 title 改成 v8.5，**Kotlin 一行不改** | 门禁全绿 |
| B 锚点漂移 | 把 `downloadJson` 改名成 `saveJsonFile` | 3 个用例红、`BUILD FAILED`，出包被拦下 |

### 9.4 导入管线

```
SAF 多选 → contentResolver.openInputStream
        → InputStreamReader + CharArray(192K)   [IO 线程]
        → evaluateJavascript("__EFB__.importAppend(name, chunk)")   [主线程]
        → importFileEnd → importCommit
        → 网页里 NavParser.parse(files) → 可选 PackCodec.encode 补机场坐标 → UI.applyData(rec)
        → Android.onDataApplied(JSON) → ViewModel 更新状态
```

几个必须记住的约束：

- **Binder 单次约 1 MB**：块按 Kotlin `String` 字符切 192K，用 `JSONObject.quote` 转义，**不用 base64**（多 33% 体积）；
- **`rec.source` 不能是 `'builtin'`**，必须是 `'app'`；也不能只改 `window.__DATASET__`，必须走 `UI.applyData` 并 `.then()` 取结果；
- **坐标必须走 `PackCodec.encode`**：手工拼 `AIRPORTS_GLOBAL` 会静默写出 (−90, −180) 这种错坐标。转换后、encode 前还做了一次全量范围校验；
- **数据包没有 `apt.dat`**：Navigraph 的 `xplane12-native` 只带 `earth_aptmeta.dat`，所以 shim 在 `AIRPORTS_GLOBAL` 为空时，按 `ICAO 区域 纬度 经度 标高` 解析 aptmeta 再 encode。实测 16698 个机场，含 ZGSZ / ZSPD；
- **只存 SAF Uri 列表**（SharedPreferences + `takePersistableUriPermission`，且容错 —— 有的 provider 不支持持久授权）。**不落派生数据包、不存在 restore 回灌、不依赖 WebView 存储**。
  网页数据只在内存里，所以 WebView 一销毁就得重导：切到别的标签再回工具页会按记住的 Uri 自动重导一次，失败过一次就不再自动重试。

### 9.5 两个 WebView 常驻

工具页的两个子页各有一个 WebView，同时挂在树上，切页只改 `View.INVISIBLE` / `VISIBLE`：

- **不用 GONE**：GONE 会把 WebView 布局成 0×0，再显示时容易白屏；
- 不重新 `loadDataWithBaseURL`，已导入的 25 MB 数据不会丢；
- `domStorageEnabled = false`：页面 `boot()` 时 `DataStore.get()` 直接落到 `renderEmptyState()`，避开旧缓存竞态。

### 9.6 航路保存与油量联动

- 方案从网页 DOM 收敛：`__EFB__.getPlans()` 读 `.plan` 卡片，key 取 `.pcopy` 的 `data-copy`（**不用 `data-plan`**，两者编号不是一套；也没有高度越界的卡片）。
- **只有点「保存」才写盘**（`RouteStore`，SharedPreferences 存 JSON）。生成、展开、复制都不落盘。
- 距离注入：`el.value = nm; el.dispatchEvent(new Event('input', {bubbles:true})); calc()`。脚本放在 `efb_patches.json` 的 `runtime.distanceJs`，Kotlin 里不写 JS 字面量，**油量 HTML 字节级零改动**。
- 切到油量页时自动填一次；用户手改过就不再覆盖，除非点「重新填入」或换了「当前航路」。

### 9.7 自定义检查单

- 内置检查单**只读**：没有编辑入口，进度键仍是「阶段序号/条目序号」，行为与 1.2.2 完全一致。
- 「复制一份」生成 `custom_<时间戳>_<随机>` 副本，**所有阶段与条目重新发 uid**（不复用原 uid，否则两份副本会串进度）。
- 副本的进度键改用 **uid**：用户可以随便重排条目，序号会平移，只有 uid 不会串位。
  `ReferenceViewModel` 的 7 个进度方法全部按 `custom_` 前缀分流：内置走 `ChecklistProgress`，自定义走 `CustomChecklistStore`。
- 编辑是图形化的、**即时保存**（输入框 300 ms 防抖后落盘），改名 / ▲▼ 排序 / 增删阶段与条目都不改 uid。

### 9.8 合规处置（阶段 0）

`.gitignore` 补了 5 条规则，`git rm --cached -r co-routes/` 已执行，磁盘文件保留（作为验收对照）。

### 9.10 1.3.1 修的那个 bug：两个 AndroidView 会抢触摸

1.3.0 的写法是两个 `ToolsWebView` 都放进 `Box`，靠 `View.INVISIBLE` 切换。
真机表现是**航路页能画出来，但怎么点都没反应**（油量页反而正常）。

原因：Compose 的 `AndroidView` 外面套着一个 `AndroidViewHolder`（ViewGroup），
**宿主本身始终可见、始终参与命中测试**。上层那个即使内部 WebView 设成 `INVISIBLE`，
点击也先被宿主吃掉，到不了下层的 WebView。

排查过程（可复用）：先把打过补丁的 HTML 单独丢进无头浏览器跑探针

```powershell
msedge.exe --headless=new --disable-gpu --virtual-time-budget=6000 --dump-dom "file:///.../patched.html"
# 探针结果：PROBE|EFB=yes|UI=object|NavParser=object|CLICK=BOUND
```

`CLICK=BOUND` 说明事件绑定正常，排除 HTML/补丁问题 → 锁定在 Android 视图层。

修法：`FrameLayout` + 只挂当前页的 WebView（见 `ToolsWebView.kt` 头注释）。
未挂载的实例仍活着，切回来是 `addView`，不是重新 `loadDataWithBaseURL`，数据与滚动位置都不丢。


### 9.11 1.3.2：网页导入接通 + 油量页选择器皮肤

**① 「点击导入数据没反应」**：面板里那句「把导航数据拖到这里，或点击选择文件」最终是
`$('fileNav').click()`，而 WebView 没有 `onShowFileChooser` 回调 —— 原生文件选择器根本弹不出来。
修法是在 shim 里把这个 `<input type=file>` 的 `.click()` 换成 `Android.pickNavFiles()`
（`ToolsBridge` 新增的 `@JavascriptInterface`），由 App 弹 SAF 选择器，选完仍走分块注入管线。
导入成功后 shim 自动 `closeDataPanel()`，避免用户盯着「已选 0 个文件」以为没导进去。

> AIP 表与数据包两个入口这次没接（仍是无反应），它们不在本期范围内。

**② 油量页的机型 / 规章弹层**：原生 `<select>` 在 WebView 里弹的是系统下拉，和页面深色主题完全脱节。
改成自绘底部弹层，落在独立资源 `assets/tools/efb_fuel_skin.js`，由 `efb_patches.json` 的
`skin` 补丁按 `</script>\s*</body>` 注入内存 —— **磁盘上的 `fuel_calc.html` 仍然字节级原样**，
以后换新版 HTML 皮肤会自动重放。

关键约束（改这个皮肤时必须守住）：

- `<select>` 只能隐藏、不能删除：`applyAircraft()`、`calc()`、URL 参数、`runSelfTests()`
  全都以它为唯一数据源；
- 选中后必须 `sel.value = v` **再派发 `change`**，否则页面参数不重算（实测：换机型后
  `TAS` 440→140、`OEW` 35400→1700 才是正确的）；
- 触发按钮是 `<button>`，并且 `preventDefault()` + `stopPropagation()`：它躺在 `<label>` 里，
  不拦的话点击会转发给那个隐藏的 select；
- 弹层用的颜色全部走页面已有的 CSS 变量（`--panel2/--line/--accent`），页面没有浅色主题，
  不需要额外适配。

无头浏览器验收探针（改完必跑）：

```
PROBE|CSS=yes|TRIGGERS=2|NATIVE_HIDDEN=yes|OPEN=yes|ITEMS=70|GROUPS=4|CLOSED=yes|AC_VALUE=7|MATCH=yes
PROBE|AC=0->69|TAS=440->140|OEW=35400->1700|INFO=最大起飞重量 MTOW3,175 kg
```

**③ 底部标签**：第 4 个标签从「工具」改名「航路/油量」（`EfbApp.kt`），`Tab.Tools` 的 key 仍是 `tools`，

### 9.12 1.3.3：同名递归——「点了不弹文件选择」的真凶

`ToolsBridge` 里我写了：

```kotlin
private val pickNavFiles = onPickNavFiles        // 回调属性

@JavascriptInterface
fun pickNavFiles() { main.post { pickNavFiles() } }   // 桥方法
```

Kotlin 的解析规则是 `foo()` **优先匹配成员函数**，而不是 `foo` 属性的 `invoke()`。
于是 `main.post { pickNavFiles() }` 投递的是一个「再次调用自己」的 Runnable ——
每次点击都在主线程排队一个新任务，无限空转，回调一次都没执行，文件选择器自然不弹。
**编译零警告、运行不崩溃、测试也发现不了**，只有反编译才能看见：

```
private static final void pickNavFiles$lambda$0(ToolsBridge);
   0: aload_0
   1: invokevirtual  // Method pickNavFiles:()V     ← 调的是自己
```

修法是回调属性改名 `onPickRequest`，修完后：

```
   1: getfield      // Field onPickRequest:Lkotlin/jvm/functions/Function0;
   4: invokeinterface // Function0.invoke:()Ljava/lang/Object;
```

**结论（写进规范）**：桥类里凡是「参数 → 私有字段」的转发，字段名一律加前缀（`onXxx` / `xxxRequest`），
**绝不能与 `@JavascriptInterface` 方法同名**。同类代码（`applyData` / `emitEvent`）本来就没撞名，这次是我新加的那个撞了。

另外给文件选择器加了 `runCatching` + Snackbar：以后再失败会明说，不会让用户对着一个没反应的按钮猜。

### 9.14 1.3.5：航路页顶栏窄屏适配 + 三个导入入口全接通

**① 顶栏裁字 / 页面溢出**：`#toolbar` 写死 `height:50px`、单行不换行，而页面自带的
`@media(max-width:900px)` 只改了 `body` / `#main` / `#sidebar`，**完全没管工具栏**。
手机上 `.brand`（含那串「自备导航数据 · CAAC 官方航路 · 国内走廊 · 高度层滚轮」副标题）
被压成三行，实测高 71px，然后被 50px 的高度裁掉；`#dataTag` 又是 `white-space:nowrap`，
把整行撑宽。两个症状同源。

修法（写在 shim 的 `injectToolbarFix()` 里，纯 CSS，不动 HTML）：

```css
@media (max-width:900px){
  #toolbar{height:auto;min-height:50px;flex-wrap:wrap;row-gap:8px;padding:8px 12px}
  #toolbar .brand{flex:1 1 100%;margin-right:0;min-width:0}
  #toolbar .brand small{display:none}          /* 副标题太长，窄屏藏掉 */
  #dataTag{order:2;flex:1 1 64px;min-width:0;overflow:hidden;text-overflow:ellipsis}
  #toolbar button{order:3;flex:0 0 auto;height:34px}   /* 按钮不压缩 */
  #toolbar #btnGen{flex:1 1 auto}
}
```

实测：390px 视口顶栏 80px、品牌行 21px 完整、`KIDS_OUTSIDE=0`、`DOC_OVERFLOW=no`；
1000px 视口 `TB_H=50`、副标题 `display:block`，行为与改动前一致。

**② 三个导入入口**：`#fileNav` / `#fileAip` / `#filePack` 都是隐藏的 `<input type=file>`，
WebView 没有 FileChooser 回调，三个都点不开（之前只接了第一个）。
现在 `hookFileInputs()` 用 `{fileNav:'nav', fileAip:'aip', filePack:'pack'}` 一次性全钩上，
桥方法从 `pickNavFiles()` 改成 `pickFiles(kind)`，`importBegin(kind)` 带类型，
`importCommit()` 按类型分派 `applyNav` / `applyAip` / `applyPack`。

`applyAip` 的关键约束：页面内部的 `btnApplyAip` 用的是 UI 闭包里的 `current.pack`，外部拿不到，
所以用 `lastPack`（上次成功应用的数据包）作为 pack，没有再把 `window.__DATASET__` 重新
`PackCodec.encode` 兜底。`ctxCaac` / `ctxPriority` 在 shim 里跨次记住，换数据时沿用，
避免导数据包把之前导入的 CAAC 航路表冲掉。

门禁：`requiredConsts` 增加 `AipParser`（8 个），以后新版去掉它会直接构建失败。

> AIP 的 `stats.airports` 是本表涉及的机场数，不是数据集机场数；提示文案按页面原口径显示。
